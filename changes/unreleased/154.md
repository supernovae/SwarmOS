- In `--fork` mode, a GitHub server error (5xx) or timeout while posting a coordinator request no longer leads to a duplicate request. Each request now carries a random request nonce. After an ambiguous post, swarm looks through the issue's recent comments for that nonce and continues with the comment it finds. If the comment is not there, swarm posts it once more. It never posts a third time, and if it cannot tell whether the request was posted, it says so and gives the nonce. Comment reads that fail with a server error or timeout are retried briefly, and an error that persists names the request. The nonce is only used to match the comment; the coordinator still checks every request against GitHub and coordination state. Upstream repositories must update their SwarmOS Fork Coordinator workflow so it accepts the new field. Until they do, older coordinators reject these requests, and swarm now reports that rejection right away instead of waiting for the timeout.
